# Pro1-X mainline SFOS: sensors and camera — research (2026-10-23, read-only)

Legend: [C] confirmed (path/URL seen), [I] inferred, [R] recalled from training, unverified.

## 1. Sensors

### What NixOS does
- [C] modules/sensors.nix: no IIO devices; accel/gyro/mag/ALS/prox live on the ADSP (SSC). Stack = hexagonrpcd (serves sensor registry/config from device/hexagonfs, `-f /dev/fastrpc-adsp -d adsp -s -R /var/lib/hexagonrpcd`) + iio-sensor-proxy (libssc). README.md:321-327 says the same.
- [C] hexagonrpcd = linux-msm/hexagonrpc PR 27 head `40e5041` ("Support for writing files", FadyAckad) + packages/hexagonrpc-sns-registry.patch (new `sns_registry` interface, 7 files). PR 27 is **closed, not merged** (closed 2026-09-21, merged=false; api.github.com/repos/linux-msm/hexagonrpc/pulls/27). Upstream main after that: only "rpcd: Map -h to help". Alpine ships hexagonrpcd 0.4.0-r3 (no write support). => hexagonrpcd for SFOS means packaging a fork with two patches.
- [C] udev: `KERNEL=="fastrpc-adsp", ENV{IIO_SENSOR_PROXY_TYPE}+="ssc-accel ssc-proximity"`, ACCEL_MOUNT_MATRIX "-1, 0, 0; 0, -1, 0; 0, 0, 1"; waits for QRTR service 400. disableRecovery: ADSP crash loop can freeze the phone.
- [C] iio-sensor-proxy 3.9 (Debian 3.9-1 src/): drv-ssc-accel.c, drv-ssc-compass.c, drv-ssc-light.c, drv-ssc-proximity.c. NEWS 3.9: "SSC sensors are now supported through libssc. Light and compass sensor are enabled by default, accelerometer and proximity remain experimental". Default rule only adds `ssc-light` on fastrpc-adsp*. libssc does NOT create IIO devices; it is a GLib library (QMI/protobuf over QRTR) consumed in-process.
- [C] libssc 0.4.4 (codeberg DylanVanAssche/libssc, Alpine community): headers libssc-sensor-{accelerometer,gyroscope,magnetometer,compass,light,proximity}.h; deps libqmi-glib >=1.33.4 (QRTR-only patches per pmaports MR 4050), protobuf-c, libqrtr-glib, glib, gobject-introspection. pmaports MR !4050 (SDM845, 2023) = the origin of libssc + iio-sensor-proxy integration.

### sensorfw (SFOS 5.1.0.11: sensorfw-qt5 0.15.1, qt5-qtsensors-plugin-sensorfw installed; stage1.log:1919-2006)
- [C] Adaptor dirs upstream (api.github.com/repos/sailfishos/sensorfw/contents/adaptors): iioadaptor, *-evdev, *-ascii, alsadaptor-sysfs, hybris* (accel, als, gyro, mag, orientation, pressure, prox, rotation, stepcounter, wakeup, georotation), plus legacy MeeGo ones. **No D-Bus/SensorProxy/libssc adaptor exists.**
- [C] iioadaptor: one class registered as accelerometeradaptor, gyroscopeadaptor, magnetometeradaptor, alsadaptor, proximityadaptor; udev-enumerates IIO devices, matches `<sensor>/input_match` against the IIO device name, reads scan elements via buffered /dev/iio:deviceN. Rootfs has /usr/lib64/sensord-qt5/libiiosensorsadaptor-qt5.so (plus evdev/ascii/sysfs variants; no hybris libs).
- [C] Plugin selection (core/loader.cpp): config key `plugins/<adaptorname>` -> `lib<name>-qt5.so` in the plugin dir; fallback = adaptor name itself. Config: /etc/sensorfw/primaryuse.conf + sensord.conf.d/*.conf (rootfs ships 10-sensord-default.conf, 20-sensors-default.conf; upstream config/ also has 60-sensors-DEVICE.conf template). 20-sensors-default.conf gates availability on ssu-sysinfo hw-settings Feature_* flags -> droid-config-qx1050 needs a csd hw-settings.ini (victara ref has sparse/usr/share/csd/settings.d/hw-settings.ini).
- [C] PinePhone ref (ref/droid-config-pinephone/sparse/etc/sensorfw/primaryuse.conf): `[plugins] accelerometeradaptor = iiosensorsadaptor` (same for orientation/als/magnetometer/gyroscope/proximity); sensord.conf.d/90-dontbeevil.conf: per-sensor `input_match=mpu6050|stk3310|lis3mdl`, `intervals`, `transformation_matrix = "0,1,0,-1,0,0,0,0,-1"`, `threshold=19` for prox. Pattern comments out hybris-libsensorfw-qt5.
- [C] victara ref clone is a **hybris** config as checked out (hybris*adaptor primaryuse.conf, etc/gst-droid, droid-hal-device.conf), so it is not a mainline sensor example here.
- [C] net.hadess.SensorProxy (3.7 xml): only HasAccelerometer, AccelerometerOrientation (string), AccelerometerTilt, LightLevel(+Unit), ProximityNear, Compass.CompassHeading. **No raw accel xyz, no gyro, no raw magnetometer.** sensorfw's accelerometersensor, gyroscopesensor, magnetometersensor, rotation/compass chains and Qt Sensors clients need raw samples -> a SensorProxy D-Bus adaptor can at best feed orientation/als/prox, never accel/gyro/mag. Also native-common has no iio-sensor-proxy package (index checked), so that route would mean porting it too.
- [C] Searched for an SFOS mainline Qualcomm-SSC precedent: sailfishos-native org repos, sailfish-on-dontbeevil org, native-common index, web search. None found. The OnePlus 6/6T SFOS port is hybris on kernel 4.9 (forum thread 19875), not mainline.
- [C] Repo availability in SFOS 5.1 base (stage1.log package list): protobuf-lite yes; protobuf-c, libqmi, libssc, hexagonrpc: not present. native-common has libqrtr-glib 1.2.0+git1 only. port/packages/ already carries qrtr, rmtfs, tqftpserv.

### Recommendation (sensors)
- Design: **sensorfw adaptor plugin linking libssc directly** (`libsscadaptor-qt5.so`, one class registering the five adaptor names exactly like iioadaptor; GLib main loop in a worker thread feeding the adaptor buffers), selected via `[plugins] accelerometeradaptor = sscadaptor` etc. in /etc/sensorfw/primaryuse.conf. Not the D-Bus bridge (data loss above). Orientation/compass chains then come free from sensorfw. [I]
- Mount matrix: NixOS "-1,0,0; 0,-1,0; 0,0,1" -> sensorfw `transformation_matrix = "-1,0,0,0,-1,0,0,0,1"` for accelerometer and gyroscope; verify on device. [I]
- Packaging needed (OBS or local rpm): libqmi (>=1.33.4, check QRTR-only support), protobuf-c, libssc 0.4.4, hexagonrpcd fork (PR27 head + sns-registry patch), hexagonfs data package (device/hexagonfs, device-specific; README: sensors-collect.sh regenerates), systemd unit ordering (fastrpc node wait, QRTR 400 wait, remoteproc recovery off), udev for /dev/fastrpc-adsp group. [I]
- Risk: iio-sensor-proxy 3.9 marks SSC accel/prox "experimental"; README says sensors "Partly" and autostart can hang the phone. [C]
- Effort: packaging 3-4 libs + hexagonrpcd fork ~1 week; sensorfw plugin (~500-800 lines C++, modelled on iioadaptor) + config + on-device tuning ~1-2 weeks; total 2-4 weeks of sessions, mainline-kernel debug not included. [I]

## 2. Camera

### What NixOS does
- [C] modules/camera.nix + overlay.nix: libcamera 0.7.2 (nixpkgs), `pro1x-libcamera` = two patches (device/libcamera/{imx582,s5k4h7}-sensor.patch: CameraSensorHelper + camera_sensor_properties entries) + tuning files installed to share/libcamera/ipa/simple/{imx582,s5k4h7}.yaml. Pipeline = libcamera **simple** pipeline handler on qcom-camss with **software ISP** (README:316-317 "Tuning is limited to what libcamera's software ISP offers"). Consumed via PipeWire/WirePlumber SPA (LD_LIBRARY_PATH override), apps Snapshot + cameractr; focus via tools/cam-focus.sh (dw9800 VCM).
- [C] Kernel side is in device/kernel/patches/pro1x-camera.patch: DTS regulators (PCA9534-switched IMX582 rails), new drivers imx582.c, s5k4h7.c, dw9800.c, and camss.c additions for sm6115 (CSIPHY2, CSID2, VFE2 in *_res_2290). pro1x-kernel-sfos shares the same patch set (overlay.nix), so SFOS kernel already has it.
- [C] libcamera simple pipeline lists `{ "qcom-camss", {}, true }` (swISP) already in v0.4.0 and master.

### SFOS side
- [C] Rootfs 5.1.0.11: jolla-camera 1.3.2, qt5-qtmultimedia-plugin-mediaservice-gstcamerabin, gstreamer 1.26.11 with libgstvideo4linux2.so (v4l2src) and libgstcamerabin.so; **no libgstlibcamera.so, no libcamera** in the jolla repos. gecko-camera plugins upstream = droid + dummy only (browser camera out of scope).
- [C] native-common OBS (repo.sailfishos.org/obs/nemo:/devel:/hw:/native-common/sailfish_latest_aarch64/aarch64/): libcamera-0.4.0+git1-1.19.13.bso (downloaded, listed): ships /usr/lib64/gstreamer-1.0/libgstlibcamera.so, ipa_soft_simple.so + soft_ipa_proxy, ipa_rkisp1/rpi_vc4/mali_c55, v4l2-compat.so; also libcamera-tools, libcamera-devel; gstreamer1.0-plugins-good 1.22.10+v4l2, qt5-qtmultimedia-*-5.6.2+v4l.20230905 (sailfishos-native qtmultimedia "with V4L support"), v4l-utils 1.26.1. No pipewire/shutter/rawfish there.
- [C] Qt camerabin source selection (sailfishos/qtmultimedia mer-5.6 camerabinsession.cpp, strings also in rootfs libgstcamerabin.so): `QT_GSTREAMER_CAMERABIN_VIDEOSRC` (comma list, optional `driver=element`), else hard default `v4l2src`; device set via `device` string on the video-source or `camera-device` int on the camera source. libcamerasrc uses `camera-name`, so primary/secondary selection via env alone will not work -> small qtmultimedia patch or wrapper likely needed. [I]
- [C] jolla-camera-hw.txt (victara ref, hybris) keys: [apps/jolla-camera/{primary,secondary}/{image,video}] imageResolution, videoResolution, viewfinderResolution(+_4_3/_16_9), isoValues, whiteBalanceValues, focusDistanceValues, flashValues, exposureCompensationValues, resolutionText_*; rootfs default /etc/dconf/db/vendor.d/jolla-camera.txt has only generic keys, so a qx1050 hw.txt is mandatory. jolla-camera QML has no gst-specific code (grep'd).
- [C] PinePhone SFOS: config ships cameras_setup.sh (media-ctl formats for ov5640/gc2145) + v4l-utils, no libcamera -> v4l2src path with the +v4l qtmultimedia. Issue sailfish-on-dontbeevil/droid-config-pinephone#55 "Camera with libcamera" (2020) ended inconclusive. PinePhone Pro: working app is piggz's **Shutter** (harbour-shutter, libcamera direct, Silica flavor, uses native-common libcamera); forum 2023: "libcamera isn't plugged into the SailfishOS standard API so other apps relying on camera don't work". No evidence anywhere of jolla-camera running on libcamerasrc.

### Recommendation (camera)
- Step 1 (days): install native-common libcamera + libcamera-tools on the device; `cam -l`, `cam -c1 --capture=5`; `gst-launch-1.0 libcamerasrc ! videoconvert ! waylandsink`. 0.4.0 lacks the imx582/s5k4h7 helpers: expect "uncalibrated" tuning and gain model mismatch; rebuild libcamera (0.4.0 + the two patches rebased, or bump to 0.7.x) in a local OBS/sfdk project with the yaml files under ipa/simple/. [I]
- Step 2 (uncertain, 1-2 weeks): jolla-camera via `QT_GSTREAMER_CAMERABIN_VIDEOSRC=libcamerasrc` in /var/lib/environment/nemo/*.conf + jolla-camera-hw.txt; patch camerabinsession to set `camera-name` for front/back. Fallback with known-good precedent: package Shutter (Silica) like PPP. [I]
- Kernel is not the blocker; camss/dts/drivers already in the SFOS kernel build. Verify /dev/media0 + `media-ctl -p` first. [C/I]
